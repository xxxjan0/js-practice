При подготовке товаров для UI нужно было добавить новые поля, не меняя исходный массив, сначала я пробовал мутировать объекты напрямую, присваивая product.priceString = что-то, что нарушало условие, затем переписал через map с возвратом нового объекта { ...product, priceString: ... }, и добавил сразу несколько полей за один проход

В каталоге по категориям требовалось вывести категории, а под ними товары, я сначала выводил все категории подряд, а потом для каждой фильтровал товары, но забыл, что категория может быть пустой, и тогда выводился пустой блок, поэтому добавил условие if (filtered.length > 0), иначе писал Нет товаров

Нужно было получить несколько разных списков из одного массива пользователей (активные, администраторы, email-адреса, количество неактивных), я пытался сделать всё в одном цикле, но код получился запутанным и грязным, поэтому переписал на отдельные цепочки filter и map, хотя можно было пройтись один раз и заполнить все переменные, но так нагляднее для  примера

В таблице заказов внутри каждого заказа есть массив товаров, нужно было посчитать общее количество товаров и итоговую сумму, я сначала пытался делать эти расчёты прямо внутри генерации строки таблицы, но быстро запутался в скобках, поэтому вынес вычисления в отдельные переменные перед join, и ещё забыл, что price и count - числа, но при перемножении без parseFloat они иногда вели себя как строки из-за особенностей получения данных, поэтому явно преобразовал их в числа

Задача с фильтрацией и сортировкой каталога требовала применить поиск по названию, фильтр по категории и сортировку по цене, я сделал отдельные чистые функции, но сначала перепутал порядок: сортировал до фильтрации, из-за чего сортировка слетала после фильтрации, потом поменял местами, а также забыл, что поиск по названию должен быть нестрогим (через includes), а не точным равенством

Не понимал, чем чистые функции отличаются от обычных, в примере сделал функции, которые не меняют глобальные переменные и возвращают новый результат, а для sortProducts использовал [...products], чтобы создать копию массива перед сортировкой и не мутировать исходный, что и является признаком чистоты
